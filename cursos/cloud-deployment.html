Cloud Deployment

Docker, CI/CD, infraestrutura como código e observabilidade. A trilha que encerra a frase "funciona na minha máquina" e coloca o seu projeto no ar com deploy repetível, seguro e com custo previsto.

O ponto de partida

Deploy virou evento de risco, não rotina

"Funciona na minha máquina"

Versão de biblioteca diferente, variável de ambiente esquecida, caminho absoluto. O ambiente que só existe no seu notebook não é entregável — é acidente aguardando data.

Subir versão à mão, de madrugada, com medo

SSH, git pull, reiniciar serviço, torcer. Sem rollback testado, qualquer erro vira indisponibilidade — e você vira o único que sabe fazer.

Fatura de nuvem que ninguém previu

Instância ligada no fim de semana, disco órfão, bucket público, serviço gerenciado dimensionado no chute. O susto chega no boleto, nunca no deploy.

Quebrou e ninguém soube primeiro

Sem log centralizado, métrica ou alerta, quem avisa que o sistema caiu é o cliente. Você descobre o problema pelo WhatsApp, não pelo monitoramento.

Perfil

Para quem é — e para quem não é

✓Esta trilha é para você se

  • Constrói solução (app, API, dashboard, modelo) e precisa colocá-la no ar com as próprias mãos.
  • É cientista ou analista de dados cujo projeto morre no notebook por falta de deploy.
  • É desenvolvedor e quer sair do FTP/SSH manual para CI/CD e infraestrutura como código.
  • Precisa justificar custo de nuvem e segurança para sócio, gestor ou cliente.
  • Quer entender AWS, Azure e GCP pelo conceito — sem ficar preso a um provedor.

✕Não é para você se

  • Nunca usou linha de comando nem Git — combine um nivelamento conosco antes.
  • Quer aprender a construir pipeline de dados em si — a trilha é Data Engineer.
  • Quer serving e monitoramento específico de modelo de ML — veja ML Engineer.
  • Busca curso preparatório de certificação de fornecedor. Ensinamos prática de engenharia; a certificação pode vir como consequência, mas não é o objetivo.

Pré-requisitos

Uso confortável de terminal (navegar, executar script, ler saída de erro), Git funcional (commit, branch, push, pull request) e uma linguagem de programação em nível de escrever uma aplicação simples — Python, Node ou similar. Também ajuda entender o básico de HTTP: requisição, resposta, status code. Não exigimos experiência prévia com nuvem nem com Docker.

Resultado

O que você sai fazendo

Containerizar qualquer aplicação

Dockerfile enxuto com multi-stage build, .dockerignore, variável de ambiente e Docker Compose para subir aplicação com banco local. Ambiente idêntico em toda máquina.

Automatizar do commit ao deploy

GitHub Actions com teste, build, publicação de imagem e deploy. Pull request que falha teste não chega a produção — a esteira decide, não a pressa.

Declarar infraestrutura em vez de clicar no console

Terraform com estado, plano, módulo e ambiente separado (dev/homolog/prod). Criar e destruir infraestrutura inteira em minutos, com revisão antes de aplicar.

Escolher o serviço certo pelo custo, não pelo nome

VM, container gerenciado, serverless e plataforma: latência, escala, custo e complexidade de cada um. Você decide com número, não com o que está em evidência.

Saber que quebrou antes do cliente avisar

Log centralizado, métrica, health check, alerta acionável e tracing básico. Observabilidade como parte do deploy, não como projeto separado depois.

Proteger credencial e controlar gasto

IAM com permissão mínima, secret fora do repositório, rede e grupo de segurança, orçamento com alerta. Segurança e custo tratados como requisito, não como susto.

Programa

Cinco módulos, do container à produção monitorada

Você traz um projeto seu — ou usa o que fornecemos — e o leva do zero até publicado em nuvem, com deploy automatizado, alerta e custo medido.

01 Fundamentos de nuvem e o modelo mental certo 8h
  • O que é nuvem de verdade: computação, armazenamento e rede como serviço
  • IaaS, PaaS, SaaS e serverless — o que cada camada terceiriza para você
  • Região, zona de disponibilidade, escalabilidade e o mito do "100% no ar"
  • Modelo de responsabilidade compartilhada e segurança
  • Leitura de preço: como a fatura é composta e onde ela surpreende
  • Comparativo AWS, Azure e GCP: serviços equivalentes lado a lado

Entrega: escolha justificada de provedor e arquitetura para o seu projeto final.

02 Docker em profundidade 8h
  • Container vs. máquina virtual: isolamento, namespace e o que muda na prática
  • Dockerfile: camadas, cache e por que a ordem das instruções importa
  • Multi-stage build: imagem final pequena e sem ferramenta de compilação
  • Volumes, redes e variável de ambiente sem segredo no código
  • Docker Compose para desenvolvimento local com banco de dados
  • Registry: publicar e versionar imagem

Entrega: aplicação do projeto final containerizada e publicada em registry.

03 Infraestrutura como código com Terraform 8h
  • Por que clicar no console não escala: drift e ambiente não reproduzível
  • Terraform: provider, resource, variável e output
  • Estado remoto, lock e trabalho em equipe sem conflito
  • plan antes do apply: revisar mudança antes de executar
  • Módulos e ambientes separados: dev, homologação e produção
  • Rede básica: VPC, sub-rede, grupo de segurança e exposição pública

Entrega: infraestrutura do projeto criada por código, com dois ambientes.

04 CI/CD e deploy sem downtime 8h
  • Pipeline: estágio de teste, build, publicação e deploy
  • GitHub Actions: workflow, secret, ambiente e aprovação manual
  • Estratégias de deploy: rolling, blue-green e canary
  • Rollback rápido e testado — o plano que ninguém escreve até precisar
  • Health check, readiness e por que o balanceador precisa saber
  • Migração de banco de dados em deploy sem quebrar a versão antiga
  • Kubernetes: o conceito, quando faz sentido e quando é excesso

Entrega: pipeline que leva o commit até produção automaticamente, com rollback.

05 Observabilidade, segurança, custo e projeto final 8h
  • Log centralizado, estruturado e pesquisável
  • Métrica, dashboard e alerta com threshold que não gera ruído
  • Tracing básico: achar onde a requisição lenta aconteceu
  • IAM e permissão mínima; secret manager; rotação de credencial
  • LGPD em nuvem: residência de dado, criptografia e acesso
  • Orçamento, alerta de gasto e desligamento de recurso órfão
  • Apresentação do projeto final com feedback individual

Entrega: aplicação em produção com monitoramento, alerta e custo documentado.

Dúvidas frequentes

Antes de você se inscrever

Vocês ensinam qual provedor de nuvem?
Usamos AWS como referência principal, por ser a mais presente no mercado brasileiro, e mostramos o serviço equivalente em Azure e GCP em cada tópico. Docker, Terraform e GitHub Actions são neutros de provedor — ou seja, a maior parte da trilha vale para qualquer nuvem, inclusive para a que a sua empresa já usa.
Vou ter custo de nuvem durante o curso?
O projeto é dimensionado para a faixa gratuita dos provedores, e a primeira prática inclui configuração de alerta de orçamento. Se a sua conta não tiver acesso ao free tier, o gasto típico do projeto final fica em poucos reais por mês — e ensinamos a destruir toda a infraestrutura com um comando ao terminar, para não deixar recurso cobrando.
É curso preparatório para certificação AWS ou Azure?
Não, e preferimos dizer isso com clareza. Ensinamos prática de engenharia de deploy: container, pipeline, IaC e observabilidade. Alunos que fazem a trilha costumam ter base sólida para certificações de nível associado, mas não cobrimos o edital item por item nem simulados. Se o seu objetivo exclusivo é passar numa prova específica, um curso focado no exame rende mais.
Kubernetes entra na trilha?
Entra como conceito e critério de decisão no módulo 04: o que é, que problema resolve, qual o custo operacional e quando um container gerenciado simples já basta. Não é uma trilha de Kubernetes — aprofundar em cluster, operador e service mesh exigiria um curso inteiro. Se for a sua necessidade, combinamos aulas particulares sobre isso.
Sou de dados, não sou dev. Serve para mim?
Serve, e é um dos públicos que mais se beneficia. Cientista e analista que aprende a containerizar e publicar para de depender de terceiros para colocar modelo ou dashboard no ar. O requisito é ter terminal e Git funcionando e conseguir escrever um script simples — não é preciso ser engenheiro de software.
Posso usar o projeto da minha empresa como projeto final?
Sim — é o cenário ideal, e o mais comum nesta trilha. Você sai com deploy real funcionando em vez de exercício. Só pedimos cuidado com credencial e dado sensível: nada de secret de produção em repositório de aula, e seguimos o que está na nossa Política de Privacidade.

Da próxima vez, deploy pode ser um comando — não um evento.

Quem sabe publicar com pipeline, rollback e alerta deixa de ser gargalo e passa a ser quem destrava o time. É a habilidade que transforma projeto pronto em projeto no ar.
